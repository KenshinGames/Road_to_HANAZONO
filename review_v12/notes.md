# v0.12 実ブラウザレビュー（Chromium 横向き 1060×600、play.html）

撮影: `shoot.js`（puppeteer-core + /opt/meta-chromium/chrome）。シードセーブは jsdom で実セーブを作り改変して注入（本番コードにデバッグ導線は入れていない）。対象試合は帝都学園戦（12月・予選決勝、選手能力を一律78に底上げした確認用セーブ）。

## 確認結果（全て問題なし）

- コンソールエラー / pageerror: **0件**（全ページ）
- ページ全体のはみ出し: 全5画面で document スクロール幅・高さ = 1060×600（ページスクロールなし、パネル内スクロールの原則を維持）
- `01_prematch_scout.png`: 対戦確認。スカウティング欄の末尾に「🎯 弱点ヒント」が2件表示（帝都=キック多用への対策＋キック精度への警告）。いずれも相手の内部データ（style/ace/skill）から導いた内容で、画面の可読性・右カラムの戦術ボタンにも影響なし
- `02_match_commentary.png`: 試合中の実況。キックオフに季節言及（12月・年の瀬の寒空の下）、トライ実況に得点者名＋季節フレーズ、相手PGは2種類の異なる文が出現。同じ文の繰り返しは目視でも確認されず
- `03_halftime.png`: ハーフタイム場面。右カラムの采配パネル冒頭に形勢サマリー（スコア／前半の得点内訳／主導権の傾向＋後半への一言）が表示され、同じ内容が左の実況ログにも残る。実集計（トライ2・PG0／相手PG2）が実際の得点経過と一致することをログと突合済み
- `04_factors.png`: 試合後の勝因表示。要因が降順（36/34/21/9%）に並び、最大要因「能力差（最大）」がフル幅バー＋太字ラベル、要因ごとに色分け（青/橙/紫/灰）。% の合計は100で従来どおり
- `05_squad_forms.png`: 選手一覧。調子が固定サイズ（20px）の顔アイコンだけで表示され、色（紫/水色/黄/赤/ピンク）と表情だけで5段階が判別できる。ラベル文字が無くなった分、行の横幅が選手によって揺れない。詳細パネルの調子欄も同じアイコン＋注記テキストのみ

## 備考

- 実況パターンは計42種（基本36＋帝都専用6）。試合内の重複回避は M.usedComm（試合内のみの一時データ）で管理し、セーブ形式は無変更
- ハーフタイム集計は M.hist（得点イベントの実記録）ベース。停止点のない試合（練習試合など）でも40分時点で実況ログに1回だけ出る
- 既存挙動として、実況ログは自動スクロールで最下部に合わせるため、先頭行が半行だけ見切れることがある（v0.12 以前からの仕様で、今回の変更とは無関係）
- play.html 総容量は 2,173,028 bytes（写真 data URI 5件を含む。v0.11 からはテキスト増分のみ）
