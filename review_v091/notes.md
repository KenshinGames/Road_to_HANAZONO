# v0.9.1 実ブラウザレビュー（Chromium 横向き 1060×600 ／ 縦向き 390×844）

撮影: shoot.js（play.html タイトル／index.html タイトル／縦向きタイトル。各ページともセーブを消した状態で撮影）

## 実装内容
- タイトル画面の SVG ヒーローバナー（banner('home')）を廃し、ChatGPT 生成の夕景イラスト（花園ラグビー場・赤い客席・夕日、文字なし）を `.titlephoto` の全面背景（cover）に採用
- 素材は 1672×941 → 幅1600px・JPEG 品質82に最適化して 258,933 bytes（元 360,483 bytes）。base64 data URI（345,244文字）として style.css に埋め込み。play.html は build_play.py のインライン化で同じ CSS を含む（完成品 849,580 bytes）
- スクリムは2層の linear-gradient（左→右の減衰＋下→上の減衰）。本文カードは `.title-card`（半透明ダーク＋blur）にして、写真の上でも説明文・難易度注記まで読めるようにした
- 横画面では `.titlewrap.titlephoto` が幅いっぱい（max-width 解除）に広がり、コンテンツは下部寄せ

## 確認結果
- `01_title_landscape_play.png`（play.html）: 写真が 1032×580 で全面表示。タイトル・サブコピー（v0.9.1）とも白文字＋影で可読。カード内の2ボタン（ふつう／チャレンジ）と注記まで判読可能。ヒーロー（〜297px）とカード（309〜568px）に重なりなし。document は 1060×600 に一致（ページスクロールなし）、console/page エラー 0 件。就任ボタンのクリックで目標画面へ遷移することも確認
- `02_title_landscape_index.png`（index.html）: play.html 版とスクリーンショットのハッシュが完全一致（同一表示を確認）。メトリクス（写真の矩形・子要素の矩形・背景 data URI）も全項目一致
- `03_title_portrait.png`（縦向き）: cover で夕景中央が切り取られ、タイトル・カード・両ボタンが写真パネル内に収まる。横はみ出しなし、致命的な崩れなし（パネル下に余白が出るのは縦向きフォールバックとして許容範囲）
- 写真の見せ場（左の赤い客席、右の夕日とゴールポスト、照明塔）は上半分に残り、スクリムで隠れすぎていない。手前のボールはカード裏になるが、構図上の優先度（可読性）とのトレードオフとして許容

## 指摘・修正
- 初回撮影で index.html／縦向きが目標画面になったのは、file:// の localStorage がページ間で共有され、先行ページのセーブを読み込んだため（ゲーム側の不具合ではない）。shoot.js で各ページの読み込み前にセーブを消去するよう直して再撮影し、上記の結果を得た
- CSS・レイアウトの修正は不要と判断（可読性・収まり・写真の見え方とも基準を満たす）
