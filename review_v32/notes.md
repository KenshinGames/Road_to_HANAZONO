# review_v32 — v0.32（v1.7）「操作しやすさの見直し」調査・監査・確認記録

作成：2026-11-16（Claude Code）。発端は Takada の指示「ゲームを全体的に見直して、直すべきところを指摘して。より操作しやすいゲームにして」。

**表示と操作の配置だけの変更**で、ゲームの数値・判定・乱数消費・セーブ形式・localStorage キーは変えていない（下の「ソーク同値性」と qa_v32 で確認）。

## 1. 調べ方

作者の実機（iPhone 15 Pro・横画面 852×393、セーフエリアを引いた中身は約 734×372）を Chromium で模擬し、
1年目のシーズンを「手で遊ぶ手順」でなぞった（週は毎週カードを選ぶ・試合は1ブロックずつ進める）。画面ごとに次を記録した。

- 押せる要素（ボタン・セレクト・押せる行）の大きさ
- 最初の表示で、スクロールしないと見えない操作
- 画面ごとのタップ数

道具は scratchpad の probe.js（リポジトリには入れていない）。同じ考え方の検査を `shoot.js` の **tap 検査**として監査に組み込んだ（§4）。

### C. 進むボタンの位置が定まらない・連打の事故

- 試合だけ、進めるボタンが右の欄の上にあり、試合終了の「次へ」は内訳の下。ほかの画面は全部「下のバー」。
- 下のバーの決定ボタンは画面をまたいで同じ位置に出る（次へ → 確認した → 指示を確定して月を始める）。

- ハーフタイムの指示 → 後半の戦術変更は、同じ位置に次の選択肢が出る。

### D. 通知・案内

- 実績の通知が画面の下の中央に出て、決定ボタンの文字を 3.4 秒隠す。シーズンの締めなどで4件まとまると、画面の真ん中を縦にふさぐ。

  枠が余ったまま「新年度を始める」を押しても、何も知らせない。

## 3. 直したこと（v1.7）

決まり：**①判断に使う操作はスクロールの先に置かない ②進む・決定は下のバー ③押せる範囲は 44px 級 ④通知は決定ボタンに重ねない**。

- **試合**：スコアボードを1段に（高さ 95→約50px）。勝負どころの選択肢は「名前・決め手の1行・成功率の印（右）」に詰め、3つも4つも1画面に全部出す。
  「試合を進める／次へ」は下のバーに固定。場面の間は決定ボタンが「采配を選ぼう」（押せない）になり、選手交代は下のバーのボタンで右の欄を切り替える
  （交代が済んだら采配に戻る）。進行中の右の欄は「今日の采配」（戦術・後半の形・キッカー・マーク・交代の残り）。
  ハーフタイムの形勢の箱と「キーマン：◯◯」は右の欄に重ねない（左の実況とカットインに同じものがある）。後半の戦術変更は成功率の印を出さない。
- **対戦確認**：戦術は 2×2 のタイル（名前／効く場面▲。週のカードの効果の札と同じ言い方）。PGキッカーとエースのマークの指名を並べて表示。
  メンバー編成・結果のみ表示は下のバーの左、キックオフは右。
- **目標**：5つを1行ずつ（名前・おすすめ・達成ボーナス）。説明文は、選んでいる目標の分だけ左のガラスに。
- **月頭指示**：初回ヒントと案内のバーは左の列（情報の列）へ。右の列は指示の盤面だけ。
- **遊び方**：「戻る」と「チュートリアルをもう一度見る」を下のバーへ。
- **スカウト**：獲得ボタンを能力のすぐ下（成功率と同じ行）へ。比較表は帯を1段にして、獲得の行を表の下端に貼り付け（能力を見比べながら押せる）。
  枠がいっぱいなら残りは押せない見た目に。枠が余っている間は決定ボタンに「（獲得枠 あと n 名）」。名前は折り返さない。
- **押せる範囲**：HUD・案内のバー・月頭指示のボタン列・おまかせは、見た目を変えずに当たり判定を広げた（`::after`）。HUD のアイコンは幅 40px。
  タブ 40px、下のバーの決定ボタン 44px、選手一覧の行 36px、メンバー編成の行 40px。
- **通知**：画面の上から出す。一度に2件まで（残りは順に）。
- **案内（チュートリアル）**：進みに追いつく。その画面の操作を一度やったら次の番へ（週＝最初の1週、試合＝最初の采配で終わり）。
  「終了する」は控えめな見た目にして「わかった」と離した。
- **連打よけ**：画面が切り替わった直後 0.28 秒、場面が出た直後 0.4 秒、週を選んだ直後 0.25 秒は、実際のタップを受けない。
  プログラムからの click()（QA・ソーク・監査）は対象外（`isTrusted` で見分ける）。

監査（§4）を小さい機種まで流して見つかり、追加で直したもの：

- **選手交代の「交代をやめる」**：控えの一覧のいちばん下（スクロールの先）にあった。見出しの行の右へ移した。
- **選手のプロフィール欄**（選手一覧 → プロフィール）：右の欄の幅が 220px ほどしかなく、見出しの札「学年／ポジション」が1文字ずつ縦に折れていた
  （v1.4 の見た目の作り直しからそのまま。作者の実機でも同じ）。立ち絵を小さくし、札は折らずに値を次の行へ送る。
- **スカウトの比較表**：見出しの行（顔・名前）が 130px あり、最初の表示で能力の行が1つも見えなかった。顔と名前を横に並べて低くした。
  帯の「部の格 ◯◯ ／」は HUD にあるので畳み、「獲得枠 n名（選択中 m名）」が切れずに読めるようにした。
- **案内のバーと対戦確認の指名**（高さ 402 の iPhone 16 Pro／17 Pro）：詰める段を高さ 440 まで広げた。
- **いちばん小さい機種**（iPhone 12/13 mini、中身の高さ 354px）：目標の5つ目・月頭指示のセレクト・後半の戦術変更の4つ目が、数 px 足りずに切れていた。
  この高さだけ行の間を詰める段（`max-height: 380px`）を足した。
- **最初の試合を「結果のみ表示」で飛ばしたとき**：早送り中の描画で案内（5／5）が「見せた」ことになり、一度も出ずに終わっていた。
  早送り中は数えず、結果の画面で一度出す。

## 4. 監査に足した検査（`shoot.js` の tap 検査）

これまでの監査（はみ出し・重なり・枠内の見切れ）は「文字が切れていないか」を見るもので、スクロールする欄の中に操作が隠れていても合格だった。
今回の問題はその隙間にあったので、同じ道具に **操作の検査**を足した。以後の合格条件に入れる。

| 検査 | 中身 |
|---|---|
| tap-hidden | 判断に使う操作（下のバー・HUD・案内のバー・活動カード・おまかせ・月頭指示のボタン列とセレクト・タブ・選択肢・対戦確認の指名）が、最初の表示で 98% 以上見えているか |
| tap-small | 押せる範囲を `elementFromPoint` で実測（`::after` で広げた分を含む）。進行に使う操作は 高さ44・幅40px 以上、そのほかは 高さ32px 以上。一覧の中でスクロールの端にかかっている行は測らない |
| tap-scroll | 当たり判定を広げる透明な `::after` が、スクロールしなかった箱をスクロールさせていないか |

当たり判定の `::after` は `scrollWidth／Height` を膨らませるので、そのままでは「文字の見切れ」と区別がつかない（最初の実行で clip が 528 件出た）。
`::after` の中身を CSS 変数 `--tapx` に置き、監査が `:root` の `--tapx` を `none` にして見た目の検査をし、戻してから tap 検査をする。
HUD は横画面で `overflow: hidden` だったため、上下に広げた当たり判定まで切れていた（実測 37px）。横だけ切る `overflow-x: clip` に変えて 45px。

手直しの確認用に、`IOSDEV=_ipmini,_ip17p` のように機種を絞れるようにした（合否の記録は全機種で取る）。

## 6. 作者の判断を仰いだ案と、その決定（2026-11-16）

1. **おまかせ（月末まで自動）の確認** → **入れる**（作者「1タップ挟もう」）。
   1回目で同じ場所（右の列の下端）が「やめる」（左・控えめ）と「⏩ おまかせで月末まで進める」（右・主役）に変わり、2回目で進む。
   確認のボタンは出た直後 0.4 秒は実際のタップを受けない（2度押しで確認まで通らない。実機と同じタップで確かめた）。
   週のカードを選ぶ・画面を離れると確認は取り消し。確認の状態はセーブにも乱数にも関係しない
   （寄り道をしても乱数の消費と結果は同じことを qa_v32 [11] で確認）。ソークと古い QA は2回押す形に追随（文言に「おまかせ」を残したので、
   `btn('おまかせ')` で押すソークの駆動はそのまま2回押しになる）。
2. **試合の自動進行** → **まだ入れない**（作者「まだしない」）。
3. **タイトルのボタン** → **44px にする**（作者「大きくしていいよ。クレジットに任せよう」）。
   タイトルの制作表記の1行（制作：Kenshin Takada ／ Muse との共同開発）を外し、遊び方のクレジット節に任せた。空いた高さでタイトルのボタンを全部 44px にした。

## 7. 残っている点

- 得点の札（「トライ！ +7点」）は、スコアボードを1段にしたぶん、出ている間は得点の数字に重なる（札の中に同じスコアがある）。
- 案内のバーが出ている最初の試合は、左の実況の欄が低い（15 Pro で約 100px）。最初の采配を選ぶとバーが消えて戻る。
- 対戦確認の左のキーマン対比は、案内のバーが出ている間、下が切れてスクロールになる（情報の欄。操作は右と下に全部出ている）。
- 連打よけの時間（0.28／0.4／0.25 秒）は机上で決めた値。実機で「反応が鈍い」と感じたら短くする（`tapTooSoon` の呼び出し3か所）。
